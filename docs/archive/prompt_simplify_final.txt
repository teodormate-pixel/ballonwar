## SITUAȚIE
Codul din `teren_proceduaral.gd` (2409 linii) e prea complex: threading + pending_post_sync + generation_tasks + LOD + overrides în thread. Rezultat: coliziunea dispare, loading lent, gaps între chunk-uri, crash-uri.

## CE AI DE FĂCUT: RESCRIE GENERAREA SIMPLU

**Principiu:** Generare pe main thread cu time budget (ca în versiunea originală), fără thread-uri, fără post_sync, fără LOD.

### Pas 1: Ștergi tot ce ține de threading
Ștergi variabilele:
- `generation_mutex`
- `generation_tasks`
- `_pending_post_sync`
- `_pending_post_sync_keys`
- `MAX_THREADS`
- `_sync_budget_ms`

Ștergi funcțiile:
- `_capture_noise_params()`
- `_thread_create_noise()`
- `_thread_get_biome_weights()`, `_thread_get_dominant_biome()`, `_thread_get_biome_profile()`
- `_thread_surface_height()`, `_thread_surface_color()`
- `_thread_biome_color()`, `_thread_block_type_color()`
- `_thread_get_base_block_type()`, `_thread_adjust_height()`
- `_generate_chunk_worker()`
- `_sync_generation_results()`
- `_process_pending_post_sync()`

### Pas 2: Rescrii `_process_chunk_queue()` original (cu time budget)
Revii la varianta simplă de dinainte de threading:
```gdscript
func _process_chunk_queue() -> void:
    if not initial_generation_started:
        return
    if generating_chunk:
        return
    generating_chunk = true
    var frame_start: int = Time.get_ticks_msec()
    var processed_this_pass: int = 0
    while not chunk_generation_queue.is_empty():
        if generation_time_budget_ms > 0 and processed_this_pass > 0:
            if Time.get_ticks_msec() - frame_start >= generation_time_budget_ms:
                break
        var data: Dictionary = chunk_generation_queue.pop_front()
        chunk_generation_pending.erase(data["key"])
        if not _is_chunk_within_render_distance(data["cx"], data["cz"]):
            continue
        _genereaza_singur_chunk(data["cx"], data["cz"], data["key"])
        processed_this_pass += 1
        if not terrain_ready_emitted:
            generation_completed_chunks += 1
            _emit_generation_progress("Generating terrain...")
    generating_chunk = false
    if chunk_generation_queue.is_empty():
        _mark_terrain_ready()
    elif processed_this_pass > 0:
        call_deferred("_process_chunk_queue")
```

### Pas 3: Rescrii `_genereaza_singur_chunk()` să facă tot pe main thread
Include în ea:
- Creare mesh cu `_create_chunk_surface_mesh_extended()`
- Coliziune cu `mesh.create_trimesh_shape()` (se face acum, nu mai târziu)
- Apă: `_build_water_surface()`
- Structuri: `genereaza_structuri_specifice_zonei()`
- Peșteri: `_genereaza_pesteri()`
- Overrides: `_sync_modified_blocks_from_overrides()`
- MultiMeshInstance3D setup

### Pas 4: Asigură-te că `_clear_chunk_visuals` nu lasă chunk-uri pe jumătate
Când un chunk e re-generat (de exemplu după săpare), `_clear_chunk_visuals` șterge tot, iar `_genereaza_singur_chunk` adaugă tot înapoi în același frame (sau următorul, dacă time budget expiră).

### Pas 5: Verifică `extra = 1` border
`_create_chunk_surface_mesh_extended` folosește `extra = 1` ca border sample. Asta asigură că marginile chunk-urilor se suprapun cu 1 unitate → fără gaps.

### Pas 6: Parametri optimi pentru telefon
În `_ready()` setezi:
```gdscript
lod_enabled = false
mobile_mode = true
distanta_randare = 2    # 5x5 = 25 chunk-uri
cave_enabled = false
generation_time_budget_ms = 8
```

### Pas 7: Verifici că `sapa_bloc_la_pozitie` funcționează corect
La săpare:
1. `_set_override_for_world(wx, wy, wz, BlockType.AIR)` — marchează blocul ca aer
2. `_remove_block_visual(wx, wy, wz)` — șterge collision body și updatăm MultiMesh
3. `_request_rebuild_for_world(wx, wz, 0)` — re-generează chunk-ul (ca să actualizeze mesh-ul de suprafață)

`_request_rebuild_for_world` trebuie să funcționeze fără să piardă coliziunea. Cheia: `_genereaza_singur_chunk` creează root + mesh + coliziune în același apel, deci nu există fereastră fără coliziune (cu excepția unui frame între `_clear_chunk_visuals` și terminarea generării).
